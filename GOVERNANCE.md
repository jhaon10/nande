# Gobernanza

## Roles

| Rol | Cómo se llega | Qué puede hacer |
|-----|---------------|-----------------|
| **Colaborador/a** | Hacer un aporte | Abrir Issues y Pull Requests |
| **Revisor/a** | Aportes constantes | Aprobar Pull Requests de su área |
| **Mantenedor/a** | Postular tras historial constante | Asignar Issues, fusionar PRs, coordinar un área |
| **Comité** | Elegido entre mantenedores | Resolver desacuerdos y decisiones estratégicas |

Al inicio, el fundador coordina todo. El objetivo es repartir ese poder lo antes posible.

## Áreas

Backend · Frontend · Datos · UX/UI · Traducciones (i18n) · Comunicación y terreno

## Cómo se toman decisiones

1. **Consenso tácito:** se propone, se discute, y si nadie objeta en el plazo, se aprueba.
2. Si hay desacuerdo, decide el mantenedor del área.
3. Si persiste, decide el comité.
4. Las decisiones grandes quedan escritas en `docs/decisions` (ADR/RFC).

## Neutralidad

Cualquier decisión que ponga al proyecto del lado de un partido, candidato o gobierno
se rechaza. Ver [MANIFIESTO](MANIFIESTO.md).

## Dinero

Si el proyecto recibe donaciones o fondos: se administran de forma pública
(por ejemplo, Open Collective), se rinde cuentas periódicamente y no se aceptan
fondos de partidos ni campañas.

## Sucesión

Si el fundador desaparece o se retira, el comité de mantenedores asume la coordinación.
Los accesos críticos (dominio, hosting, cuentas) deben estar compartidos entre al menos
tres personas de confianza.
